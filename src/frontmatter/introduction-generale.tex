\chapter*{Introduction générale}
\addcontentsline{toc}{chapter}{Introduction générale}
\markboth{Introduction générale}{Introduction générale}

Une alerte de sécurité doit pouvoir être examinée. Pour un opérateur, connaître
la classe prédite ne suffit pas : il faut retrouver l'observation analysée,
le modèle utilisé et les éléments qui ont conduit au signalement. Ce projet
aborde la détection d'intrusions IoT à partir de ce besoin, en reliant
l'évaluation de modèles sur des flux enregistrés à une application
qui conserve et présente leurs résultats.

Le travail s'appuie sur RT-IoT2022, un jeu de données public de communications
normales et d'attaques IoT \citep{b_s_rt-iot2022_2023}. Un premier modèle distingue
le trafic normal des attaques; un second attribue une famille aux flux signalés.
La préparation des données, la comparaison des modèles et l'analyse des erreurs
précèdent leur intégration dans une API et une interface d'investigation.
L'application permet aussi de rejouer les observations du jeu de données et de
consulter séparément les alertes de signature d'un laboratoire Suricata.

La question est donc la suivante : comment évaluer cette cascade de
classification et rendre ses décisions consultables dans un prototype IoT?
L'évaluation porte sur des partitions de RT-IoT2022. Elle ne mesure pas encore
l'efficacité du modèle sur le trafic d'un autre réseau; cette distinction fixe
la portée des résultats présentés.

Le rapport comprend cinq chapitres. Le premier présente les travaux de
référence et les caractéristiques du jeu de données. Le deuxième précise les
besoins de l'opérateur et des producteurs d'observations. Le troisième décrit
les données, les composants et leurs interactions. Le quatrième explique la
réalisation et les vérifications techniques. Le cinquième compare les modèles,
analyse les erreurs de la cascade et discute les limites de l'expérience.
